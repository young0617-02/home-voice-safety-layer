# G2 预订与退款手册 v0.1

> 日期 2026-11-02 ｜ 定位：G1 结束后的"真实预付"环节，只管**收款、登记、退款、对账、判据**，不重复 G1 访谈与 G3 内测。
> 口径来源：`docs/用户验证包-v0.1.md` §5.3/§5.4/§7-G2、`docs/C端产品化路线-v0.1.md` §5/§6。
> 锁定口径：20 户中 **≥10 户完成真实预付（可退）且退款率 ≤20%** 为通过；**5–9 户**降价或改买断 + 缩到"门锁+燃气"再测 2 周；**<5 户**当天转 B2B。
> 三档：**A ¥99/年、B ¥199/年、C ¥299 买断，功能与权益范围完全一致，仅价格与有效期不同**；每户固定一档，不并列展示、不切换比价。
> **四条边界**：① 本文不写任何真实收款账号、费率、银行信息；② 不承诺具体可用日期与功能清单；③ 不收集身份证、银行卡号、CVV、支付密码；④ `synthetic=1` 的订单一律不计入判据。

## 0. 一页总览

### 0.1 预订流程

```text
[发出邀请] → [选档] → [付款] → [确认登记] → [7 天冷静期] → [退款 / 继续]
  访谈后 24h   每户固定一档   微信/支付宝/对公   回话术+台账      无理由全退      进入 G3 候选
```

| 步 | 动作 | 谁做 | 时点 | 产物 |
|---|---|---|---|---|
| 1 | 发出邀请 | 本人 | 访谈后 **24 小时**（不在现场发） | 邀请消息（含预订页链接与条款） |
| 2 | 选档 | 用户 | 收到邀请后自行选择 | 档位选择（A/B/C 之一） |
| 3 | 付款 | **用户付、本人收** | 选档后 48 小时内 | 支付凭证 / 流水号 |
| 4 | 确认登记 | 本人 | 收到付款后 2 小时内 | 订单台账一行 + 话术 2 |
| 5 | 7 天冷静期 | 用户可随时提出 | 付款成功起 7 个自然日 | 退款申请或继续 |
| 6 | 退款 / 继续 | **本人退款** | 受理 24h、到账 3–5 个工作日 | 退款记录 / G3 候选名单 |

**为什么邀请要等 24 小时**：不在访谈现场发链接，排除社交压力造成的"支持一下"型付款；24 小时后仍愿意付的，才是真实信号。

### 0.2 只有这 3 件事必须本人（或财务）做

1. **收款**：必须由本人/公司账户收，**不得让助手代收、不得用他人收款码**；收款码不进群、不挂在公开帖。
2. **退款**：必须本人复核后**原路退回**；脚本只能改状态字段，**不能代替实际退款**。
3. **开票**：必须本人/财务操作；不由助手代开，不用个人抬头替单位开票。

其余（登记、对账、报表、状态流转）可脚本化，但每天必须人工核一次差异（见 §6）。

### 0.3 一页检查表（每笔订单 60 秒）

- [ ] 户号是 P01–P20，且与 G1 名单一致（不是新户、不是亲友）。
- [ ] 档位是 A/B/C 之一，金额与档位一致（99/199/299），币种 CNY。
- [ ] 付款时间、支付方式、流水号（或回单号）三项齐全。
- [ ] 已发"付款后确认"（话术 2），并告知 7 天可退。
- [ ] 台账 `synthetic` 为 `0`（示例行必须删掉或改 0 后才能计入）。
- [ ] 没有收集身份证、卡号、CVV、家庭住址。

## 1. 表单字段

### 1.1 用户填什么（预订页，4 项）

| 字段 | 必填 | 说明 |
|---|---|---|
| `household_id` | 是 | 邀请时预填（P01–P20），用户不可改；没有户号不允许下单 |
| 联系方式 | 是 | 微信或手机号，**只收一种**；只用于订单与退款联系 |
| `plan` | 是 | A / B / C 单选；**页面只展示分到的那一档**，不并列三档 |
| 同意条款 | 是 | 勾选"我已阅读并同意预订与退款条款（版本 v0.1）"，记录 `consent_version` |

### 1.2 运营填什么（付款后登记，后台）

`amount`、`payment_method`、`payment_ref`、`paid_at`、`refund_status`、`refund_requested_at`、`refunded_at`、`refund_amount`、`note`。

> 金额由档位自动带出，**不让用户手填金额**；用户手填的金额一律不认，以支付流水为准。

### 1.3 字段表（与 `docs/订单导入模板-G2.csv` 一致）

| 字段 | 必填 | 值域 / 格式 | 谁来填 | 说明 |
|---|---|---|---|---|
| `order_id` | 是 | `G2-YYYYMMDD-###`，全局唯一 | 系统/运营 | 不用姓名、手机号当订单号 |
| `household_id` | 是 | `P01`–`P20` | 邀请预填 | 与 G1 名单一一对应 |
| `plan` | 是 | `A` / `B` / `C` | 用户 | 每户固定一档 |
| `amount` | 是 | `99` / `199` / `299` | 系统 | 必须与档位一致；不一致进差异台账 |
| `currency` | 是 | `CNY` | 系统 | 不收外币 |
| `created_at` | 是 | ISO 8601 含时区 | 系统 | 下单时间 |
| `paid_at` | 是 | ISO 8601 含时区 | 运营 | 以支付流水时间为准 |
| `payment_method` | 是 | `wechat` / `alipay` / `bank_transfer` | 运营 | 三选一 |
| `payment_ref` | 是 | 流水号 / 回单号 / 支付单号 | 运营 | **不填卡号**；截图打码后另存 |
| `refund_status` | 是 | `none` / `requested` / `refunded` / `rejected` | 运营 | 状态机见 §4 |
| `refund_requested_at` | 否 | ISO 8601 | 运营 | 用户提出退款时填 |
| `refunded_at` | 否 | ISO 8601 | 运营 | 实际退回完成时填 |
| `refund_amount` | 否 | 数字，未退款填 `0` | 运营 | 全额退时等于 `amount` |
| `consent_version` | 是 | 如 `v0.1` | 系统 | 条款改版需重新同意 |
| `note` | 否 | 短文本 | 运营 | 只写订单相关，不写家庭隐私 |
| `synthetic` | 是 | `0` / `1` | 系统 | `1` = 合成示例，**不得计入判据** |
| `cohort` | 否 | `g2` / `g3`，空按 `g2` | 系统/运营 | `g3` = G3 内测户；G4 付费转化**只统计 `g3`**；旧 16 列模板无此列时全部按 `g2` |

> **cohort 与 G4 的关系**：`g3` 是 G3 的 10 户内测 cohort。G4 的付费转化只取
> `paid_households_by_cohort["g3"] / cohort_size`，不会把 G2 的 20 户总 `paid` 当分子。
> 旧台账没有 `cohort` 列时按 `g2` 处理，避免非内测付款被误算成内测转化；
> 如需精确复核，按 `household_id` 与 G3 cohort 名单交集重算。

### 1.4 明确不收集

- 身份证号、护照号、人脸/声纹。
- 银行卡号、CVV、支付密码、短信验证码。
- 家庭住址、门牌号、小区名、门锁品牌序列号。
- 孩子姓名、学校、班级、常去地点。
- 与订单无关的聊天记录、通讯录、相册。

> 支付凭证只需要"金额 + 时间 + 流水号后 4 位 + 户号备注"；截图里的卡号、余额、姓名一律打码后再存。

## 2. 条款要点（可直接放预订页）

> 以下文本可原样放到预订页底部；对外展示前由法务按最终版本复核。**版本号 v0.1 要写进页面，并随同意记录保存。**

```text
预订与退款条款（v0.1）

1. 7 天无理由全额退
付款成功之日起 7 个自然日内（第 7 日 24:00 截止，北京时间），你可以无理由申请全额退款，不需要说明原因，不扣手续费。

2. 未达条件或无法交付，全额退
若因我方原因未能提供约定的内测条件，或无法交付，按全额退款处理；不需要你举证，也不需要你二次申请。

3. 不承诺可用时间与具体功能
当前处于验证阶段。我们不承诺具体可用日期，也不承诺功能清单；页面与演示仅用于说明交互样子，不代表最终交付范围。

4. 三档权益一致，仅价格不同
A ¥99/年、B ¥199/年、C ¥299 买断，功能与权益范围完全一致；差异仅在有效期与付款方式。A/B 为一年期，C 为买断（含 1 年更新，之后可继续使用当前版本）。

5. 退款原路退回
退款退回原支付渠道，不由他人代收、不转到其他账户；到账时间以支付机构为准，通常 3–5 个工作日。

6. 发票
可开具电子普通发票（个人或单位抬头）。申请时提供抬头、税号（单位）与接收邮箱；退款完成后对应发票作废或冲红，发票金额与实际支付金额一致。

7. 不自动续费
年费到期前不会自动扣款；是否继续由你决定，不需要提前取消。

8. 争议处理
先与我们协商（联系方式：【填：联系渠道】）；协商不成，可通过支付平台争议流程或当地消费者权益保护渠道处理。我们不设"最终解释权"。
```

**不能写进条款的话**（写了就是承诺，后续做不到会变成投诉）：

- "下个月就能用""X 月正式可用"。
- "保证支持你家的门锁/燃气/总闸"。
- "永久免费升级""终身服务"。
- "最终解释权归我方所有"。
- "一经售出概不退款"（与第 1 条直接冲突）。

## 3. 支付方式占位

> 本节只写流程与凭证要求，**不写真实账号、费率、银行信息**；具体账户信息由本人在私信中提供，不进文档、不进群。

| 方式 | 流程 | 凭证要求 | 禁止 |
|---|---|---|---|
| 微信 | 本人出示收款码/收款单 → 用户付款（备注户号）→ 回传支付截图或单号 → 核对金额与户号 → 登记 `payment_ref` | 金额、时间、单号后 4 位、户号备注；截图打码 | 收款码发群、挂公开帖、用他人码代收 |
| 支付宝 | 同上（收款码/转账）→ 回传截图或单号 → 核对 → 登记 | 同上 | 同上 |
| 对公转账 | 财务私信提供对公账户信息 → 用户转账（附言写户号）→ 回传回单 → 核对户名/金额/附言 → 登记 | 回单（打码）、金额、到账时间、附言户号 | 在文档/群/页面写账号；让用户转到与收款主体不一致的个人账户 |

**统一规则**

- 付款前先确认档位与金额，**不让用户自己填金额**。
- 只收人民币；外币一律退回并说明。
- 付款凭证只用于对账与退款，不转发、不上传网盘。
- 退款只走原路；原路不可用时（如原账户注销），必须让用户书面确认新账户，并二次核验身份（订单号 + 原支付流水后 4 位），**不得仅凭聊天里的一句话改账户**。

## 4. 退款流程

### 4.1 状态机

```text
none ──用户提出──▶ requested ──实际退回──▶ refunded
                      │
                      └──例外驳回──▶ rejected（必须书面理由 + 二次复核）
```

| 状态 | 进入条件 | 必填字段 | 下一步 |
|---|---|---|---|
| `none` | 默认 | — | 正常订单 |
| `requested` | 用户通过消息/表单提出退款 | `refund_requested_at` | 24h 内受理并回话术 3 |
| `refunded` | 已原路退回 | `refunded_at`、`refund_amount` | 回话术 4，台账关闭 |
| `rejected` | 命中 §4.4 例外，且完成二次复核 | `note` 写理由与复核人 | 48h 内书面答复 + 申诉通道 |

### 4.2 时限

| 动作 | 时限 | 超时怎么办 |
|---|---|---|
| 受理退款申请 | **24 小时**内 | 先回"已收到，正在处理"，不让用户等消息 |
| 实际退回 | **3–5 个工作日** | 超过 5 个工作日仍未到账，主动查流水并回执 |
| 驳回决定 | **48 小时**内书面答复 | 超时视为默认受理，不得拖 |
| 退款完成后告知 | 当天 | 发话术 4，附金额与到账方式 |

### 4.3 凭证留存

- 留存：退款申请截图、退款流水/回单、沟通记录、复核人。
- 位置：本地加密目录 `var/g2/refunds/`（或财务系统），**不进群、不进网盘**。
- 保留期：**90 天**（见 §7）。
- 记录：台账 `refund_status`、`refunded_at`、`refund_amount` 三列必须同步更新。

### 4.4 拒绝退款的例外（极少）与话术

**只有三种情况可以驳回**，且必须二次复核、留书面理由：

1. **同一订单已全额退款，重复申请**（查 `refunded_at` 与退款流水）。
2. **支付凭证伪造、非本人支付、涉嫌欺诈**（需有明确证据，不靠猜测）。
3. **已超过 7 个自然日，且服务已实际交付、用户在付款前已明确知悉"超过 7 天不再适用无理由退"**（须有同意版本与告知记录）。

**不能作为驳回理由**：已经开通、已经录入、影响统计、系统不好退、财务不在、人在外地。

**驳回话术（不在 5 条标准话术内，按需使用）**

> "这次退款我们没法按无理由处理，原因是【已全额退过一次 / 凭证与付款人不一致】。你可以要求二次复核，我会在 48 小时内给书面答复；也可以走支付平台争议流程。"

> 驳回不是终点：必须给申诉通道，且二次复核人不能是原处理人。

| 2 | 付款后确认 | 收到付款 2 小时内 | 收到付款，已登记：户号 P__，档位 __，金额 __ 元。7 天内可无理由全额退；有问题直接找我，不用在群里说。 | 57 |
| 3 | 退款受理 | 收到退款申请 24 小时内 | 退款申请收到，我今天内受理。原路退回，3–5 个工作日到账；到账前你不用做任何操作，我会再回你一次。 | 50 |
| 4 | 退款完成 | 实际退回当天 | 退款已原路退回，金额 __ 元，请查收。给你添麻烦了；以后想再聊用法随时找我，不推销。 | 43 |
| 5 | 失败全额退 | 确认无法交付当天 | 这次内测没能按条件提供，按约定全额退你 __ 元，原路退回，3–5 个工作日到账。不用你举证，也不用你申请第二次。 | 57 |

**字数口径**：中文字符 + 数字 + 标点（含 `¥`、`–`）；替换 `【 】`、`__` 后需重新数，**不得超过 80**。

**五条共同规则**

- 不推销、不再提其他档位、不要求"帮忙宣传"。
- 不在话术里承诺可用日期或功能。
- 退款相关只走私信，不在群里讨论某户退款。
- 红包（G1 的 ¥50）与订单退款是两件事，**不能互相抵扣**。

## 6. 对账步骤

### 6.1 命令

> **脚本状态**：截至本手册 v0.1，`scripts/g2_orders.py` 正在落地（团队任务 #29），CLI 入口可能尚未就绪。下面第 2 段的调用形态来自脚本文件头部的用法说明，**落地后必须以 `--help` 实测为准**；若参数名不同，以 `--help` 为准，不要照抄。

```bash
# 1) 先确认脚本与子命令参数（必做；若暂无输出，说明 CLI 尚未接入）
.venv/Scripts/python.exe scripts/g2_orders.py --help
.venv/Scripts/python.exe scripts/g2_orders.py reconcile --help

# 2) 脚本用法说明给出的对账形态（需经 --help 实测确认）
.venv/Scripts/python.exe scripts/g2_orders.py reconcile \
  --orders var/g2/orders.csv \
  --payments var/g2/payments.csv

# 3) 辅助命令：先校验台账、再出报告
.venv/Scripts/python.exe scripts/g2_orders.py validate --orders var/g2/orders.csv
.venv/Scripts/python.exe scripts/g2_orders.py report --orders var/g2/orders.csv --out-dir var/g2
```

**手工降级（脚本未落地时也能对账）**

1. 导出支付流水（微信/支付宝/银行）为 CSV。
2. 按 `payment_ref` + `amount` + `paid_at` 与 `docs/订单导入模板-G2.csv` 的台账逐行比对。
3. 差异写入"差异台账"（见 6.2 表），当天处理完并留处理人。

### 6.2 差异处理

| 差异类型 | 识别 | 处理动作 | 时限 | 记录 |
|---|---|---|---|---|
| 流水有、订单无 | 支付流水里有金额，台账找不到 `payment_ref` | 先查是否漏登记；能匹配户号则补登并回话术 2；不能匹配则挂"待认领"并私信付款人，**绝不默认入账** | 24 小时 | `note` 写"待认领/已补登" |
| 订单有、流水无 | 台账有 `paid_at`，流水查不到 | 标记"未到账"，**不确认、不计入判据**；24 小时提醒一次，72 小时仍无则取消订单并说明 | 72 小时 | `note` 写"未到账/已取消" |
| 金额不一致 | `amount` ≠ 流水金额 | **以流水为准**；多付原路退差额，少付补款或全额退，不"先按通过算" | 24 小时 | `note` 写差额与处理方式 |
| 重复付款 | 同一 `household_id` 同一档位多笔 | 保留 1 笔，其余原路退；退款状态记 `refunded`，退款金额写实际退回额 | 24 小时 | 两行订单都要留，不删记录 |
| 户号对不上 | 流水备注的户号不在 P01–P20 | 挂"待认领"；核对付款人联系方式；确认是 G1 户后补登，否则原路退 | 24 小时 | 不擅自改户号 |
| 档位与金额不符 | 例如选了 B 却付 99 | 先按实际付款档位与用户确认；确认后改 `plan` 或退款重付，**不静默改档** | 24 小时 | `note` 写确认过程 |

### 6.3 对账节奏

- **每天 21:00**：导出当日流水，跑一次对账，差异当天清零或挂"待认领"。
- **G2 结束日**：全量对账一次，冻结台账；之后只允许"退款"类变更，并留痕。
- **每周**：把 `refund_status` 为 `requested` 超过 3 个工作日的订单单独列出来，优先处理。
- 对账人不能同时是收款人时，由第二人复核；一人团队则**隔日自查一次**并留记录。

## 7. 隐私与保留期

### 7.1 只存必要字段

| 存 | 不存 |
|---|---|
| `household_id`、联系方式、`plan`、`amount`、`currency` | 身份证、护照、人脸、声纹 |
| `payment_method`、`payment_ref`、`paid_at` | 银行卡号、CVV、支付密码、短信验证码 |
| `refund_status`、退款时间与金额 | 家庭住址、门牌、小区、门锁序列号 |
| `consent_version`、订单备注 | 孩子姓名、学校、班级、常去地点 |

### 7.2 保留期

| 数据 | 保留期 | 到期动作 |
|---|---|---|
| 支付凭证（截图/回单） | **90 天** | 删除；台账保留金额与流水号后 4 位即可 |
| 订单台账（含退款记录） | **1 年** | 删除或匿名化（去掉联系方式，只留户号与金额） |
| 退款沟通记录 | **90 天** | 删除，仅保留"已处理"结论 |
| 同意记录（版本号） | 与订单同期 | 随台账一起删除 |

### 7.3 删除方式

1. 列出到期清单（按 `paid_at` / `refunded_at` 计算）。
2. 在本地加密目录删除对应文件；台账中把联系方式替换为 `[已删除]`。
3. 在 `note` 写 `凭证已删除 YYYY-MM-DD`，不写删除原因细节。
4. 用户要求删除联系方式：**24 小时内**删除；订单号与金额因对账/售后需要可保留，但标注"已脱敏"。

### 7.4 不外发

- 不把付款截图、回单、联系方式发到群、朋友圈、网盘、共享文档。
- 不把订单表发给第三方（除财务/审计必需，且脱敏）。
- 退款只原路；不代付、不转给"家属账户"（除非用户书面确认并二次核验）。

## 8. G2 判据与动作

> 只列阈值与动作，完整判据表见 `docs/用户验证包-v0.1.md` §7；本文不重复整表。

### 8.1 三条阈值

| # | 判据 | 目标 | 口径 |
|---|---|---|---|
| ① | 完成真实预付 | **≥10/20 户** | 任一档、真实付款、可退；`synthetic=1` 不计；未到账不计 |
| ② | 退款率 | **≤20%** | 已退款户 / 已付款户；`requested` 处理中单列，不计入已退款但要在 memo 注风险 |
| ③ | 支付转化（次判据） | **≥50%** | 进支付页 → 完成支付；只用于排除"支持一下"型虚付，不单独决定 go/no-go |

### 8.2 动作

| 结果 | 动作 | 时点 |
|---|---|---|
| **≥10 户且退款率 ≤20%** | 进入 G3；按"支付完成率最高且退款率 ≤10% 的档"确定正式档位 | 当天 |
| **5–9 户** | 降价或改买断 + **缩到"门锁+燃气"** 再测 2 周；不直接停 | 当天启动 |
| **<5 户** | **当天转 B2B**：目标客户、报价模型、各谈 3 家、拿到 1 份书面意向 | 当天 |
| 样本不足 20 户 | 分母仍按 20 计，写"样本未满，补访/补测后重判"；**不得把分母改成已付款户** | 当天 |

### 8.3 与 C 端总纲的口径差异（必须知道）

- `docs/C端产品化路线-v0.1.md` §6 的预付闸门写的是"≥10，不通过 → 停，转 B2B"，这是**粗口径**。
- 本手册与验证包 §7 的细分是：**5–9 户先降价/缩范围再测 2 周，<5 户才当天转 B2B**。
- 执行以**验证包 §7 + 本手册**为准；汇报时注明用的是细分口径，避免团队按两套阈值各说各话。

## 9. 附录：订单导入模板说明（`docs/订单导入模板-G2.csv`）

- 表头 16 列，与 `g2_orders.py` 对齐：`order_id,household_id,plan,amount,currency,created_at,paid_at,payment_method,payment_ref,refund_status,refund_requested_at,refunded_at,refund_amount,consent_version,note,synthetic`。
- 3 行示例（A/B/C 各一条），金额 99/199/299，全部 `synthetic=1`，仅用于验证导入格式；**正式使用前删除示例行或替换为真实订单**。
- 示例覆盖三种退款状态：A=`none`、B=`requested`、C=`refunded`，便于检查状态机与字段联动。
- 编码 UTF-8 无 BOM；表头必须在第一行。
- **脚本会跳过以 `#` 开头的注释行**（`read_orders` 同时跳过全空行）：可直接使用带注释的模板；仍建议正式使用时删除示例行与注释段，避免误把 `synthetic=1` 的示例当真实订单。
- 示例 3 行已用脚本的校验逻辑核对：删除注释段后 `validate` 为 0 issues。
- 时间统一 ISO 8601 含时区（`YYYY-MM-DDTHH:MM:SS+08:00`）；未发生的时间留空；未退款 `refund_amount` 填 `0`。
- `synthetic=1` 的行**不得计入 G2 判据**；统计前先过滤。
