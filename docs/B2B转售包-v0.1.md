# B2B 转售包 v0.1

> 日期 2026-11-03 ｜ 定位：C 端 G1/G2/G4 **任一不过**时的 Plan B（`docs/用户验证包-v0.1.md` §7 明确"当天转 B2B"）。
> 资产复用：决策层、确认门禁、审计表、隐私架构**原样保留**，只换交付形态（私有部署 / SDK / 白标）。
> **事实与推断分开**：事实（代码、测试、脚本）标注来源；报价标注【推断，需询价与当面验证】。
> **三条不承诺**：不承诺真实设备已验证（HA 已在 stable/2025.1/2025.2.4 真机通过，真实设备 0 台）；不承诺 C 端真实数据（0 户）；不承诺未验证能力对应的交付时间。

## 2. 三类客户画像

| 客户 | 决策人 | 预算来源 | 采购周期 | 最在意 | 常见顾虑 | 切入话术 |
|---|---|---|---|---|---|---|
| **适老化改造服务商** | 总经理 / 项目总监 | 单户改造预算（按户计） | 2–6 周，跟改造项目走 | 单户成本、交付省事、出事后有记录 | 安装维护谁做、会不会增加工期、责任怎么分 | "每户改造里加一道'危险动作确认 + 记录'，不换硬件，按户算钱。" |
| **物业 / 社区养老运营方** | 运营总监 / 项目经理 | 年度信息化或安全专项 | 1–3 个月，走比选/招标 | 合规、可审计、数据不出社区、出事能追溯 | 数据安全、等保、出事后谁担责 | "数据留在你们机房，审计归你们，我们只提供确认与导出。" |
| **门锁 / 燃气具厂商** | 业务 / 生态合作负责人 | 研发合作或模块授权 | 3–6 个月，技术评估 + 小批试产 | 差异化卖点、授权成本、责任边界 | 集成工作量、认证、售后谁负责 | "作为安全增值模块嵌进你们的 App/网关，按项目或出货量授权。" |

**共性**：三类都不是"买一个 App"，而是"给现有交付加一层可审计的安全能力"；先问"你们现在怎么处理误操作投诉"，再谈方案。

## 3. 三种交付形态对比

| 维度 | 私有部署 | SDK / 嵌入式 | 白标 |
|---|---|---|---|
| **交付物** | Docker 镜像 + HA 集成 + 策略/设备清单 + 审计导出 + 部署手册 | 核心库（决策/门禁/审计接口）+ 示例 + 接口文档 | 去品牌界面与文案 + 客户品牌 + 私有部署包 |
| **客户需具备** | Docker 或私有云、1 名运维、1 名接口人 | 研发团队（Python 3.11+）、能改自己的服务端 | 品牌与渠道、客服与售后团队 |
| **我方工作量** | 5–10 人日 / 项目（部署 + 联调 + 培训） | 10–20 人日（适配 + 联调 + 接口冻结） | 8–15 人日（品牌替换 + 部署 + 验收） |
| **报价逻辑** | 项目制年费【推断 ¥5–15 万/年】 | 一次性授权 + 年维护，或按出货量【另议】 | 项目制 + 品牌授权【另议】 |
| **主要风险** | 环境差异、真机未验证、运维依赖客户 | 接口稳定性、客户集成能力、责任划分 | 品牌方售后能力、责任归属、合规主体 |

**选择建议**：先做私有部署（最快拿到书面意向、责任边界最清楚）；SDK 放在第 2 个项目；白标只在客户有明确渠道和售后时做。

## 4. 报价模型

> 全部为【推断，需询价与当面验证】；**不写真实客户、不写成交价、不写"最低价"**。

| 模型 | 区间 | 适用 | 成本/毛利占位公式 |
|---|---|---|---|
| 按户 | **¥20–40 / 年 / 户** | 适老化服务商、物业按户收费 | 毛利/户 = 单价 −（部署摊销/户 + 运维/户 + 支持/户） |
| 项目制 | **¥5–15 万 / 年 / 项目** | 物业/社区试点、厂商联合方案 | 毛利 = 合同额 −（人日 × 人日成本 + 差旅 + 环境/硬件） |
| SDK 授权 | **另议**（一次性 + 年维护，或按出货量） | 门锁/燃气具厂商嵌入 | 授权收入 −（适配人日 + 支持人日 + 版本维护） |

**报价三原则**

1. 先问预算来源与采购方式，再给区间；没有预算信息不报底价。
2. 按户报价必须写清"含部署/运维/支持"各占多少，避免后期被当成全包。
3. 报价与"未验证能力"解绑：真实设备联调未完成前，只报"评估/试点"费用，不报量产授权价。

## 5. LOI 模板（1 页，非约束性）

```text
合作意向书（LOI，非约束性）

甲方：____________（公司/机构）
乙方：____________（我方）
日期：____ 年 __ 月 __ 日

一、合作意向
双方有意就"危险语音动作确认 + 审计"能力开展合作评估，本意向书不构成采购承诺，不产生付款义务。

二、范围
交付形态（勾选）：□ 私有部署  □ SDK 嵌入  □ 白标
能力范围：门锁 / 燃气 / 总电 / 大功率 / 撤防 / 老人呼叫 6 类危险动作的确认与审计导出。

三、阶段
1. 评估（2 周）：环境、接口、场景、责任边界。
2. 试点（4–6 周）：单点部署 + 真实场景验证（以真机联调完成为前提）。
3. 商务：另行签署合同；价格与范围以合同为准。

四、双方投入
甲方：测试环境、1 名接口人、3 个真实场景、验收人。
乙方：部署与文档、培训、问题响应；不承诺未验证能力与固定交付日期。

五、排他与保密（可选）
排他：□ 无  □ 区域/行业 __ 个月；保密：双方对技术资料与客户数据保密 __ 年。

六、有效期
自签署日起 __ 天（建议 90 天）内有效；到期未签合同自动失效。

七、其他
本意向书不构成采购承诺、不构成独家授权、不产生付款义务；正式合作以双方合同为准。

甲方（签字/盖章）：____________    乙方（签字/盖章）：____________
```

## 7. 数据与责任边界

| 项 | 边界 |
|---|---|
| 部署 | 私有部署，系统与数据在客户环境；我方不托管客户家庭数据 |
| 音频 | **不接触原始音频**；默认不存 utterance；确认令牌只在事件内，不落库 |
| 审计 | 审计记录归客户，可导出 CSV/JSON、可设保留期（默认 30 天）、可删除 |
| 账号 | 不需要客户的家庭账号、门锁序列号、支付信息 |
| 责任 | 我方提供软件与文档；设备最终执行责任在集成方/使用方；合同约定赔偿上限（建议不超过合同额，不含间接损失） |
| 保险 | 建议客户配置相关责任险；高风险项目可要求网络安全险，保费与保额按项目谈 |
| 合规 | 客户作为个人信息处理者，自行完成告知同意与影响评估；我方提供数据处理说明与最小化字段清单 |

## 8. 30 天 B2B 验证计划

| 周 | 动作 | 目标 | 判据 |
|---|---|---|---|
| W1 | 每类列 10 家、筛 9 家；发一页纸 | 3 家愿意听 30 分钟演示 | 有决策人或接口人、有明确场景 |
| W2 | 演示 3 家（本地模拟设备，5 步） | 1 家进入评估 | 对方给出环境/接口/场景 |
| W3 | 评估 1–2 家；发 LOI | 1 份 LOI 签署（非约束） | 有签字/盖章，范围与阶段清楚 |
| W4 | 复盘；调整行业与话术 | **3 家有效接触 + 1 份书面意向** | 未达标则换行业，不加免费定制 |

**不做**：不做免费 POC 定制；不承诺真机；不报最低价；不签排他。**闸门**：30 天内拿不到 1 份书面意向 → 重新评估目标客户，而不是降价。

## 9. 红线（发给任何人之前逐条核对）

1. **不写厂商名**：只用"适老化服务商 / 物业 / 门锁与燃气具厂商"类别，不点名任何品牌。
2. **不承诺真机已验证**：统一说"代码级回归通过；真机联调待完成（0/9 blocked）"。
3. **不把 455 项测试当客户现场证据**：必须注明"单机全量回归，非现场验收"。
4. **不虚构案例、客户、成交价、收入**：没有就写"暂无"。
5. **报价标【推断】**：不在无预算信息时报底价，不写"最低价/保证最低"。
6. **不贬低竞品**：不说"大厂不安全/免费方案不能用"，只讲差异。
7. **不承诺交付时间、功能清单、独家**：真机联调前不给固定日期。
8. **不把 demo 数据当真实**：演示只用模拟设备，不引用合成留存/收入。
9. **不写真实客户名/项目名/联系人**：对外材料一律脱敏。
10. **LOI 也要过法务**：非约束性不等于可以随便签。
