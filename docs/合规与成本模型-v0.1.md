## 2. 默认数据架构（privacy by design）

### 2.1 数据分级表

| 数据类别 | 是否落盘 | 保留期（建议，需法务确认） | 加密 | 访问者 | 删除路径 |
|---|---|---|---|---|---|
| 原始音频 | **否**（进程内/临时文件即删） | 0（不持久化） | 不适用 | 仅 ASR 进程内存 | 不产生；临时文件 `finally` 删除 |
| 转写文本 `audit.utterance`【事实：`hvsl/store.py:19`】 | 是（本地 SQLite `var/decisions.db`） | 30 天 | 依赖 OS 全盘加密（BitLocker/FileVault）→ **缺口：无应用层加密** | 本机用户 / HA 管理员 | 面板「删除语音文本」+ `hvsl purge` |
| 决策留痕（trace/intent/tool/targets/risk/dispatch）【事实：`hvsl/store.py:12-36`】 | 是（同上） | 90 天 | 同上 | 本机用户 / HA 管理员 | 按 trace_id / 日期 / 全量删除 |
| 设备状态 | 否（瞬时读取 HA state） | 0 | 不适用 | 进程内 | 不适用 |
| 账号信息（仅云版） | 是（云端） | 账号存续期 + 注销后 15 天 | TLS + 字段级加密 | 云端运维（最小权限，操作留审计） | App「注销账号」→ 级联删除 |
| 同意记录 `consent` | 是（本地，云版同步） | 账号存续期 + 3 年（PIPL 第 56 条记录留存要求） | 同上 | 管理员 | 随账号注销删除 |

**缺口（必须写进 PIPIA）**：现有库为明文 SQLite，且 `session_id` 可作为准标识符；第一版用 OS 全盘加密兜底，云版前须补应用层加密（SQLCipher 或字段级 AES-GCM）。

### 2.2 "不存原始音频"的实现约束

1. **进程内处理**：麦克风数据以内存 PCM buffer 进 ASR，不落盘。现状 `pipeline/asr.py:115` 接收的是文件路径，第一版改造点为流式入口；若必须落临时文件，只允许写 `var/tmp/`。
2. **临时文件即删**：写 → 转写 → `finally: unlink`，异常/超时/进程被杀同样要删；现有 `pipeline/tts.py:119` 只清 TTS 产物，缺 ASR 侧清理，属待补项。
3. **崩溃残留清理**：启动时扫描 `var/tmp/`，删除 `mtime` 超过 1 小时的孤儿音频。
4. **日志脱敏**：`utterance` 写日志前截断到 N 字符并掩码实体（人名/地址/数字串）；任何日志不得出现音频字节、音频路径清单或完整家庭地址。
5. **可自证**：沿用 `tests/test_privacy.py` 的 socket 全堵手法，新增「临时目录在跑完后为空」断言，作为回归门禁。
6. **发布形态**：生产构建不含录音回放/调试录音开关；麦克风权限显式授予（硬件路线另加物理静音与指示灯）。

## 3. 成本模型

### 3.1 单户月成本公式

```
C_month = M_asr × P_asr_min
        + (Ch_tts / 1000) × P_tts_kchar
        + (T_in / 1000) × P_in + (T_out / 1000) × P_out
        + C_cloud_fixed + C_push
        + C_support / N_households + C_pay / N_households
        + C_infra / N_households
```

| 变量 | 含义 | 取值来源 |
|---|---|---|
| `M_asr` | 每户每月云端 ASR 分钟数 | 【需实测】按"日均唤醒×平均话语时长"埋点 |
| `P_asr_min` | 云 ASR 每分钟单价 | 【需询价】`¥[__]/分钟` |
| `Ch_tts` | 每户每月 TTS 字符数 | 【需实测】回复字数 × 播报次数 |
| `P_tts_kchar` | 每千字符单价 | 【需询价】`¥[__]/千字符` |
| `T_in/T_out` | 每户每月 LLM 输入/输出 token | 【需实测】 |
| `P_in/P_out` | 每千 token 单价 | 【需询价】`¥[__]/千 token` |
| `C_cloud_fixed` | 云资源固定项（中继/HA Cloud 类服务） | 【需询价】按年费或按户分摊 |

### 3.3 盈亏平衡与敏感性（¥99/年、¥199/年、¥299 买断）

设年费 `S`、支付费率 `p`、年可变成本 `C_var = 12 × (C_month)`、年度固定成本 `C_fix`（研发摊销 + 运营）、户数 `N`。

```
年毛利/户 = S × (1 − p) − C_var
盈亏平衡户数 N_be = C_fix / (S(1−p) − C_var)
盈亏平衡云成本 C_var_max = S(1−p) − 目标年毛利
```

买断档（硬件为 0 时为软件买断；路线 2 另加 `C_hw`）：

```
毛利 = 299 × (1 − p) − C_hw − 12 × T_life × C_month − C_support_lc − C_spare
生命周期盈亏平衡月数 T_life_be = (299(1−p) − C_hw − C_support_lc − C_spare) / (12 × C_month)
```

| 定价档 | 盈亏平衡式 | ASR 分钟 ×2 | ASR 分钟 ×5 |
|---|---|---|---|
| ¥99/年 | `C_var_max = 99(1−p)`；`N_be = C_fix / (99(1−p) − C_var)` | `C_var` 增量 `= M_asr × P_asr_min × 12`，毛利同额下降 | 增量 `= 4 × M_asr × P_asr_min × 12`；若 `C_var > 99(1−p)` 则每户净亏，必须降档或提价 |
| ¥199/年 | 同上，阈值翻倍；可承受 `C_var ≤ 199(1−p)` | 同式代入 | 同式代入 |
| ¥299 买断 | 见 `T_life_be`；云成本按装机月数线性累积 | 生命周期成本翻倍，`T_life_be` 减半 | 减至 1/5，通常需要设"云功能到期转本地"兜底 |

**结论口径**：`P_*` 全部未取到，本文件不给任何具体毛利数字；敏感性只需看 `C_var` 与年费阈值的比较（×2/×5 只放大 `M_asr/Ch_tts/T_*` 三项）。
