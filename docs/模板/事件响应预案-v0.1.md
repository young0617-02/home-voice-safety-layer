# 事件响应预案（模板 v0.1）

> **【需法务复核，不构成法律意见】** 本模板为 v0.1 工作稿，须由执业律师复核后启用；文中时限除标注"内部目标"外，均须由法务按适用法律确认。
> 依据：PIPL 第 51 条（应急预案）、第 57 条（泄露补救与通知）；数安法第 29 条（风险监测、事件处置与报告）。

## 1. 适用范围与分级

| 级别 | 事件类型 | 判定标准 | 响应目标（内部） |
|---|---|---|---|
| **P1** | 越权下发 | 未确认即下发危险动作；确认令牌被绕过/重放 | 立即停用集成，30 分钟内上报 |
| **P1** | 数据泄露 | 审计库/订单/联系方式被未授权访问、丢失、篡改 | 1 小时内上报，立即隔离 |
| **P2** | 服务中断 | 集成无法加载、确认链路不可用、审计写入失败 | 4 小时内响应 |
| **P2** | 合规失效 | 同意未记录、删除请求超期、云功能误开 | 1 个工作日内响应 |
| **P3** | 其他 | 性能下降、单户配置错误、文档口径不一致 | 3 个工作日内响应 |

> **越权下发为 0 容忍**：一旦确认发生，按 P1 处理，不因"只影响一户"降级。

## 2. 发现与上报

| 环节 | 要求 | 责任人 |
|---|---|---|
| 发现 | 任何渠道（用户、监控、审计抽查、社区反馈）均须在 **1 小时内**录入事件台账 | 首位发现人 |
| 初判 | **24 小时内**完成定级与影响面初判（内部目标，非法定） | 值班技术 + 法务 |
| 上报 | P1 立即报告产品负责人与法务；P2 当日；P3 周报 | 值班负责人 |
| 对外 | 未经法务确认，任何人不得对外发布事件细节或承诺赔偿 | 全体 |

事件台账字段：`event_id, 发现时间, 来源, 类型, 级别, 影响户数, 涉及数据, 处置人, 状态, 关闭时间`。

## 3. 证据保留（先保全，再修复）

| 证据 | 来源 | 保全方式 | 注意 |
|---|---|---|---|
| 决策链路 | `audit` 表 `trace_id` 全序列 | 只读快照 + SHA-256 哈希 | 不得修改、不得先清理 |
| 运行日志 | 集成日志、HA 日志 | 原文件复制，记录时间范围 | 不含音频；含文本须脱敏 |
| 设备状态 | HA state 快照、实体清单 | 导出 JSON | 不改变设备状态 |
| 配置 | config entry、策略清单、设备清单版本 | 导出并记录哈希 | 证明当时策略 |
| 通信记录 | 出网连接记录（若启用云） | 抓包/防火墙日志 | 证明是否外发 |

**禁止**：为"让报告好看"删除、覆盖、裁剪证据；禁止在修复前清空 `audit` 表。

## 4. 处置流程

1. **隔离**：停用集成 / 关闭云开关 / 断开外网（按事件类型选择最小必要动作）。
2. **止损**：撤销泄露的凭证、令牌；重置受影响账号；回滚最近变更。
3. **取证**：按 §3 保全，记录哈希与保管人。
4. **定位**：复现路径，确认根因（代码/配置/流程/第三方）。
5. **修复**：最小改动 + 回归测试（含越权下发专项）。
6. **验证**：在隔离环境复跑；确认无二次触发。
7. **通知**：按 §5 执行。
8. **复盘**：按 §7 输出报告与改进项。

## 5. 通知用户与监管

- **法律依据**：PIPL 第 57 条——发生或可能发生泄露、篡改、丢失，应立即采取补救措施，并通知履行个人信息保护职责的部门和个人。
- **时限与口径**：由法务按适用规定确认；**内部目标**为初判后 24 小时内完成通知决策，不把内部目标写成对外承诺。
- **通知内容**（对个人）：事件性质、可能影响、已采取的措施、您可采取的措施、联系方式；**不夸大、不隐瞒、不甩锅第三方**。
- **通知渠道**：预留邮箱/手机号 + 面板公告；联系不上的户，在面板保留公告 ≥30 天。
- **监管报送**：按主管部门要求提交事件报告与整改情况，保留回执。

## 6. 越权下发专项（P1）

1. **立即**：停用集成（卸载或禁用 config entry），停止一切下发。
2. **保全**：导出涉事 `trace_id` 全链路（含 `confirmation_state`、`dispatch_state`、`idempotency_key`）。
3. **判定**：区分"未确认下发""令牌重放""策略未覆盖""设备清单漏评审"。
4. **通知**：受影响户逐户告知，说明是否已实际执行、如何手动处置（如门锁重新上锁）。
5. **修复**：补策略/补测试（必须新增回归用例，禁止只改配置）。
6. **复测**：全量测试 + 危险类别逐类遍历 + 并发确认测试。
7. **复盘**：5 个工作日内出报告，公开改进项（不披露用户信息）。

## 7. 修复与复盘

| 项 | 要求 |
|---|---|
| 复盘时限 | P1：5 个工作日内；P2：10 个工作日内（内部目标） |
| 复盘内容 | 时间线、根因、影响面、处置、改进项（负责人 + 截止日）、是否需重评 PIPIA |
| 回归 | 修复必须带自动化测试；越权类必须含"未确认不下发"断言 |
| 归档 | 事件台账 + 证据哈希 + 复盘报告，保存 **≥3 年** |
| 演练 | 每半年 1 次桌面演练（至少覆盖：越权下发、审计库泄露、删除请求超期） |
